# CLAUDE.md

Guidance for Claude Code when working in this repository.

## What this is

Alejo Cereto's portfolio: a **static, editorial one-page portfolio** (hero,
selected work with Chiikawabiyori featured first, about, contact), with an
opt-in **walkable 3D museum** offered in a section at the foot of the page. The
museum is one hall, four framed projects on the walls, a hovering "attendant"
that briefs you, and a plinth of tools; you walk it in first person and press
<kbd>E</kbd> at anything that interests you.

The static page is the site. The museum island renders nothing (and fetches
none of the 3D stack) until "Enter the museum" is pressed; it then covers the
page, and leaving it returns the visitor to where they were. See
_Progressive enhancement_ below.

Stack: **Astro 7** + **React 19** islands + **React Three Fiber 9** / three.js +
**Tailwind 4**. Static output, no backend, no tests.

> This repo replaced an older Vue 3 + Vite single-page portfolio. Nothing of it
> remains; ignore any memory of `src/components/*.vue`.

## Commands

```bash
npm install
npm run dev      # astro dev  (daemonised: `npx astro dev stop` to kill)
npm run build    # static build to dist/
npm run preview  # serve dist/ (also daemonised)
npm run check    # astro check — typecheck .astro + .tsx
npm run images   # rebuild public/projects/*.webp from src/media/projects/*.png
```

Verify changes with `npm run check` **and** `npm run build`, then look at it.
There is no test suite; the scene is verified by eye.

## The rules that matter

**Content lives in `src/data/`.** Adding a project means editing
`projects.ts` — including its `frame` (world position, which wall it faces, and
the canvas *height*). `interactables.ts` derives from it, and the HUD counter and
title card read `projects.length`. Do not hardcode a project anywhere else.

**A screenshot is a source, not an asset.** Drop the PNG in
`src/media/projects/` and run `npm run images`. That writes the WebP that
actually ships into `public/projects/`, regenerates `src/data/image-sizes.ts`,
and rebuilds `public/og.jpg`. Nothing in `src/media/` is served; nothing in
`public/projects/` is edited by hand. The originals are ~3MB of PNG and the
museum's Suspense boundary waits for all of them before the door opens, so
shipping them directly is the difference between entering in one second and
entering in ten.

**A frame declares height; width comes from the image.** `frameSize()` in
`projects.ts` multiplies the declared height by the screenshot's real aspect
ratio. Declaring both by hand is how every canvas in the room ends up subtly
stretched — the five images here range from 1.50:1 to 1.87:1.

**`museum.ts` is the single source of truth for geometry.** `WALLS` feeds both
the rendered walls and the collision solver. If you move a wall on screen without
moving it here, the invisible one stays behind. Same for `PROP_COLLIDERS` and the
furniture in `Props.tsx` — they are two halves of one fact and must be edited
together.

**Rotations follow the wall.** `rotationY` of 0 faces +z (north wall),
`PI/2` faces +x (west), `-PI/2` faces -x (east), `PI` faces -z (south). Frames sit
~6cm off the wall face; further out and they visibly float.

**Per-frame work goes through refs, not React state.** Looking around must not
re-render the component tree. `Player.tsx` and the artwork hover/focus effects
read `useMuseum.getState()` inside `useFrame` and mutate refs directly. Only the
DOM overlays subscribe to the store.

**`Stage.tsx` is the only door to the 3D stack.** three, fiber, drei and
postprocessing are ~1.3MB of the island's 1.5MB, and the island is
`client:only` — bundled together, every visitor waited for all of it before the
title card could render at all. `Museum.tsx` loads `Stage` with `lazy()`, so the
card is up in ~200KB and the museum streams in behind it. The rule that keeps
this working: **nothing reachable from `Museum.tsx`'s static imports may import
from three, fiber, drei or postprocessing.** That is why `device.ts` holds no
`THREE` constants and why the loading percentage is pushed into `store.ts` by
`Stage` rather than read from drei's `useProgress` in `StartScreen`. Check it
with `npm run build` — `Museum.*.js` should stay tiny.

**`device.ts` decides what gets rendered, and nothing else re-decides.** One
`QUALITY` object, measured once on import. The low tier keeps shadows and
ambient occlusion — without them the room is flat cardboard — and gives up the
floor's reflection probe, which is a second render of the whole room every
frame. If you add something expensive, add its switch there rather than
querying `matchMedia` in a component.

**Text in the 3D scene is drawn into 2D canvases** (`textures.ts`), not rendered
with troika/`<Text>`. That reuses the woff2 the page already downloaded instead
of shipping a 1.2MB TTF. The scene therefore waits for `document.fonts.ready`
before mounting, or the fonts get baked into the textures wrong.

**Vite must dedupe the 3D stack.** `astro.config.mjs` pins `resolve.dedupe` and
`optimizeDeps.include` for three/fiber/drei/postprocessing. Without it Astro's
React client entry gets its own second copy, with its own reconciler and Suspense
cache, and the scene hangs on the loading screen forever with no error.

## Progressive enhancement

The static portfolio in `index.astro` is the page. The museum island is
`client:only="react"` and starts with `exited: true` in `store.ts`, so it
renders nothing until the `#museum` section's button dispatches
`museum:enter`. While the museum is open it adds `body.museum-active`, which
locks scrolling and hides `.catalogue` (the wrapper around the whole page). The
`#museum` section and its nav link (`[data-museum]`) ship `hidden` and are only
revealed once the page script confirms WebGL, so no-JS / no-WebGL visitors never
see a dead button. Hovering or focusing the button dispatches
`museum:prefetch`, which warms the lazy `Stage` chunk.

Page content (hero copy, stats, skill groups, per-project `highlights`) lives in
`projects.ts` alongside the museum data. Scroll-reveal uses `[data-reveal]`,
hidden only under `html.js` (set inline in `Base.astro`'s head).

Keep it that way. Any project detail that exists only inside the canvas is
invisible to search engines and to anyone using assistive tech.

## Gotchas

- **Escape is not a key you can listen for while pointer-locked.** When a page
  holds the pointer lock, Escape is how the *browser* takes it back, and Chrome
  does not deliver that keydown to the page at all. So the pause menu is raised
  by `pointerlockchange` in `Player.tsx`, not by a key handler — which also
  catches alt-tab and clicking another window, every one of which hands the
  cursor back and leaves the visitor with nothing to click. Chrome then refuses
  `requestPointerLock` for about a second after a user-initiated release (as a
  rejected promise in newer versions, an exception in older ones), so asking for
  it back is written to shrug off a refusal: the canvas click handler asks again.
  The `"paused"` phase is what all of this exists to show.
- **`astro dev` and `astro preview` daemonise.** They return immediately and
  keep running. Use `npx astro dev stop` / `npx astro preview stop`.
- **A backgrounded tab will not start the scene.** Chrome throttles
  ResizeObserver and rAF when `document.visibilityState === "hidden"`, so R3F's
  `<Canvas>` never gets its first size measurement and sits at 300×150 forever.
  It looks exactly like a hang. Dispatching a `resize` unblocks it. This only
  bites automated/background testing — a real visitor has the tab in front of
  them.
- **`spotLight` aims at its `target`**, which three.js parents to the scene at
  the world origin. Every frame is rotated onto a different wall, so each one
  needs an `<object3D>` target inside its own group (see `Artwork.tsx`).
- **Do not pass `fallback` to `<Canvas>`.** It swallows errors from the scene
  and renders in their place, so a broken scene is indistinguishable from a slow
  one. WebGL support is checked explicitly instead.
- **Shadows stay dynamic.** `<BakeShadows/>` would be cheaper but the attendant
  drifts and the plinth knot spins; both would freeze mid-pose.
- **Soft shadows come from VSM, not `<SoftShadows>`.** drei's PCSS helper
  patches three's `shadowmap_pars_fragment` chunk against an older version than
  0.185 ships, and the result is not subtle: every lit material loses its albedo
  and the room renders flat milky grey. `Stage.tsx` sets
  `THREE.VSMShadowMap` instead, which needs `shadow-bias` left at **zero** —
  the negative bias PCF wants punches holes in a variance map. The softness
  knobs (`shadowRadius`, `shadowBlurSamples`) are in `device.ts`.
- **`fov` is vertical.** Leaving it fixed gives a portrait phone a 37° view
  across. `FRAMING` in `Player.tsx` derives the vertical angle from the aspect
  ratio on every resize so the horizontal stays roughly constant; the camera's
  `fov` in `Museum.tsx` is only a starting value.
- **Overlays inset themselves, the canvas does not.** The document asks for
  `viewport-fit=cover`, so the `.inset-safe` / `.p-safe` utilities are what keep
  UI out from under the notch and the home indicator. The reticle and the
  vignette deliberately stay full-bleed: the crosshair has to sit where the
  camera points, and a vignette that stopped at the inset would outline the
  notch.
- `store.ts` exposes `window.__museum` in dev only — handy for driving the scene
  from the console (`__museum.getState().open('tegaru')`).
